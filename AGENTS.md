This file is maintained by Olsro, the creator of PowerVLC. Never edit it by yourself without asking the developer before.

- PowerVLC is an heavily tuned VLC fork based on VLC 3.x
- Supports Mac OS X 10.2 and newer, Linux (Ubuntu 18.04 era or newer as an appImage), Windows XP SP3 and newer. Maintain compatibility with all the supported platforms, and degrade features gracefully on older systems when it is necessary, and warn the developer if a new development can add a regression on any of the supported platform. PowerVLC intent to continue to support machines like my oldest iBook PowerPC G3 600 MHz with 256 MB of RAM and an ATI Rage Mobility 128 so make appropriate technical choices when coding new features & UIs.
- At this moment, we maintain 3 different UIs: Modern (Mac OS X 10.7+), Legacy (Mac OS X 10.2+), Qt (Linux/Windows). When a new feature is maintained or a bug is fixed, check always for all the UIs we support because the end user experience should be on-par in terms of quality
- Reference build documentation is "BUILD-POWERVLC.md"
- Reference changelog is maintainted in "CHANGELOG-POWERVLC.md" If the developer asks you for a new developement, asks him what the next version should be and when the release is planned so you can maintain regularily that document during the dev. This document should mention all changes compared to the previous version, which means you shouldn't point the own regression you add during the developement of the current version as it would be confusing to read for the end user that will read it. Please respect the formatting with the sub titles by taking example on what was done for the 2.0.0 update. Look at the latest update that already exists in the "CHANGELOG-POWERVLC.md", if the update is already specified to a date of today or in the future and if it is titled as "UNRELEASED", update its changes directly without asking what the current update is because you found a proof that's the current update that is worked on. The developer will need to remove manually the "UNRELEASED" text.
- All the docs & scripts related to machines & the local environment of the dev should be in the scratchpad which is not committed
- Avoid adding new docs on the project, the developer must request to add a new documentation explicitly
- Don't handle branches & commits by yourself and don't create worktrees in this project, excepted if requested directly by the user during a session
- If the work on current session requires testing and the developer does not specify a specific machine to test on, test directly on the current machine, and if it is a Mac don't forget to test both UIs (Legacy & Modern) + Qt on Linux using the harness with Docker. The developer may be busy, so try to not take focus and control & screenshot only at the necessary scope (often the windows related to PowerVLC).
- When the developer asks you to update or make translations, never call an external API like Google Translate: do the translations by yourself on all the languages you know and are certain to provide a good quality.
- Don't rebuild for all platforms excepted if the developer request for it, focus on the platforms you are testing on the current work. If you believe a test would benefit for a specific slice (for example G3's), request the user to give you access to a machine in the test bank.
